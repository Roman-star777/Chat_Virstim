# Chat_Virstim

Telegram міні-апка і бот для внутрішньої роботи фірми: задачі, документи, працівники.
План і схема даних: див. документ «План: міні-апка і бот для фірми».

## Що вже є (крок 2)

- Екран «Задачі»: розділи Прострочено / Сьогодні / Цього тижня / Пізніше / Виконано, фільтри з лічильниками, смуга «виконано N з M».
- «Нова задача»: текст, виконавець (Роман / Сергій / Саша / Усі), термін, «Важливо», «Нагадати».
- Закрити задачу може лише виконавець. Задача «Усі» закривається, коли відмітили всі троє.
- «Працівники»: список, тип договору, години, PDF, «хто і коли змінив», історія змін.
  Роман і Сергій можуть усе; Саша бачить список, змінює лише тип договору і скачує PDF.
- Вхід лише через Telegram: сервер перевіряє підпис initData, доступ мають лише привʼязані 3 людини.

Ще немає: бот у групі й нагадування (крок 3), документи й ШІ (крок 4), задачі з чату (крок 5).

## Як влаштовано

- `src/app` — міні-апка (Next.js) і серверні адреси `/api/*`.
- `src/lib` — логіка: перевірка підпису Telegram, дати за Прагою, розділи задач, PDF.
- `supabase/migrations` — схема бази з RLS і правилами (хто що може змінювати).
- `tests` — автоматичні тести логіки (`npm test`) і прав доступу на справжньому Postgres (`npm run test:db`).

## Змінні середовища (лише у Vercel, ніколи в коді)

Див. `.env.example`. Секрети (`TELEGRAM_BOT_TOKEN`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_JWT_SECRET`)
вводить власник у Vercel → Settings → Environment Variables.

## Як пускаються люди

1. Роман задає свій Telegram user_id у `BOOTSTRAP_TG_USER_ID` (дізнатися: написати боту @userinfobot).
2. Роман відкриває міні-апку: його акаунт привʼязується до імені «Роман».
3. Сергій і Саша відкривають міні-апку: бачать «Доступ заборонено, запит надіслано».
4. Роман (або Сергій) на екрані «Задачі» бачить запит і обирає, хто це. Після цього людина входить.

## Команди

```
npm install
npm test          # тести логіки
npm run test:db   # тести прав на тимчасовому Postgres (потрібен встановлений PostgreSQL)
npm run build
```
